## 一、A 计权的数字实现

### 模拟原型

```
H_A(s) = K_A · s⁴ / [ (s+ω₁)² (s+ω₂) (s+ω₃) (s+ω₄)² ]
```

极点频率（Hz）是**规范性**的，不要圆整：

| 极点 | 频率 | 重数 |
|---|---|---|
| f₁ | 20.598997 | 二重 |
| f₂ | 107.65265 | 单 |
| f₃ | 737.86223 | 单 |
| f₄ | 12194.217 | 二重 |

常见的 `12200` 是个流传很广的错误。`K_A = 7.39705e9` 我们也**不用**——
它是按圆整极点算的，与上表有约 0.1% 偏差。改为数值归一化到 1 kHz 处 0 dB，
一次性消掉这个差异以及双线性变换引入的整体增益。

### 6 个零点，不是 4 个

`s → ∞` 时 `H_A ~ K_A/s²`，所以除原点 4 个零点外还有 **2 个零点在无穷远**。
双线性变换把 `s = ∞` 映到 `z = -1`，于是数字域为：

```
H_d(z) = g · (1 - z⁻¹)⁴ (1 + z⁻¹)² / ∏(1 - pᵢ z⁻¹)
```

分解为三个二阶节：

| 节 | 分子 | 分母 |
|---|---|---|
| 1 | `(1 - z⁻¹)²` | `(1 - p₁z⁻¹)²` |
| 2 | `(1 + z⁻¹)²` | `(1 - p₂z⁻¹)(1 - p₃z⁻¹)` |
| 3 | `(1 - z⁻¹)²` | `(1 - p₄z⁻¹)²` |

**漏掉 `(1 + z⁻¹)²` 会让高频响应完全错掉**——低频端 `(1-z⁻¹)⁴` 给出
+24 dB/oct 上升，高频端靠 `(1+z⁻¹)²` 给出 −12 dB/oct 下降。

### 双线性畸变：偏差出现在哪、有多大

把每个极点精确锚定在其规范频率上（本实现的做法），会让**低频段**尽可能准，
代价是把偏差推到高频端。48 kHz 及以下实测：

| fs | 20 Hz | 63 Hz | 1 kHz | 2 kHz | 4 kHz | 8 kHz |
|---|---|---|---|---|---|---|
| 8 000 | +0.05 | +0.17 | 0.00 | +0.09 | — | — |
| 16 000 | +0.07 | +0.06 | 0.00 | +0.01 | +0.53 | — |
| 22 050 | +0.09 | +0.04 | 0.00 | 0.00 | +0.25 | **+5.12** |
| 32 000 | +0.10 | +0.03 | 0.00 | 0.00 | +0.13 | +1.53 |
| 44 100 | +0.10 | +0.02 | 0.00 | 0.00 | +0.08 | +0.71 |
| 48 000 | +0.11 | +0.02 | 0.00 | 0.00 | +0.07 | +0.59 |

（表内为相对 IEC 61672-1 标称值的**绝对偏差**，单位 dB。）

**两条结论：**

1. **取证频段 20 Hz–2 kHz 在所有采样率下都准确到 0.3 dB 以内**，包括
   蓝牙 HFP 的 8 kHz。本项目的噪声能量全在这里，所以低采样率下
   A 计权数值**仍然可用**——不要因为看到 `degraded` 标记就停止报告。
2. `degraded` 标记警告的是**高频段**：22.05 kHz 下 8 kHz 处偏 5 dB。
   后果是「若声源含显著高频能量，A 计权**总级**会被低估」，
   而各八度带 1 kHz 及以下不受影响。

第 1 条由 `tests/stability.rs::a_weighting_is_accurate_in_the_evidence_band_at_every_rate`
钉住，第 2 条由 `a_weighting_deviation_grows_above_2khz_at_low_rates` 钉住。

### 为什么全链路用 f64

A 计权的双极点贴近 z ≈ 0.9973、双零点在 z = 1.0。f32 下这对零极点抵消的
系数舍入误差会抬高 20 Hz 附近的噪声底，直接影响「−50.5 dB @ 20 Hz」这个
指标。48 kHz 的吞吐量不值一提，录音存 f32、计算用 f64。

## 二、时间计权作用在**平方后**的声压上

正确形式：

```
y[n] = α·x[n]² + (1-α)·y[n-1],   α = 1 - exp(-1/(fs·τ))
```

**不是**作用在幅度上。判据：IEC 规定 Slow 计权（τ = 1 s）的衰减率是
**4.34 dB/s**，而

```
10·log₁₀(e) / τ = 4.343  ✓
```

只有 α 作用在平方上才得到这个数。作用在幅度上会得到约 8.7 dB/s，
差一倍。`metrics::tests::slow_weighting_decays_at_iec_specified_rate` 锁定这条。

**α 从公式现算，绝不硬编码**——硬编码的字面量无法跟随采样率变化，
而本项目里采样率是运行时才知道的。

### Leq 不加时间计权

Leq 是纯能量平均，与 Fast/Slow 是**两条独立路径**。把两者混在一起是常见错误。

## 三、为什么触发路径绝不能过 A 计权

A 计权在目标频段的衰减：

| 频率 | 20 Hz | 31.5 Hz | 63 Hz | 100 Hz | 125 Hz |
|---|---|---|---|---|---|
| 衰减 | −50.5 | −39.4 | **−26.2** | −19.1 | −16.1 dB |

脚步能量在 **63 Hz 八度带**达到峰值。触发链若过 A 计权，等于在检测之前
先扔掉 26–39 dB 的信号。

因此本项目**强制分离两条路径**：

- **触发路径**：20–200 Hz 带通，**未计权**，快，可丢弃
- **取证路径**：宽带、校准、A 计权，必须可信

**绝不把滤波后的触发信号写进录音**——录音永远写原始麦克风信号。

## 四、绝对声压级：能做到什么、做不到什么

`cpal` 只给归一化浮点数，**驱动层完全没有绝对声压参考**。没有校准，
「邻居达到 68 dB(A)」这种陈述是不可辩护的。

校准流程：声校准器（IEC 60942）施加已知声压，标准值 **94 dB SPL
（1 Pa RMS）@ 1 kHz**，测得此时数字电平 `r_cal`：

```
offset = L_cal - dBFS(r_cal)
L_p    = dBFS + offset
```

### 两个容易忽略的细节

1. **1 kHz 处 A 计权恰好是 0.00 dB**——这正是标准选 1 kHz 的原因。用 1 kHz
   校准音时，在 A 计权通路上读数免修正。但若用 250 Hz 校准器（A 计权在该处
   是 −0.3 dB），必须在 C 或 Z 计权下校准，否则要手工补回。

2. **自由场修正**：校准器提供的是**压力场**信号，而 IEC 61672 的容差按
   **自由场**定义，两者在 1 kHz 差 0.1–0.2 dB。所以许多厂商把目标读数定为
   93.8–93.9 而非 94.0。本项目把决定权交给用户——`Calibration` 记录用户
   填的参考值（`reference_db_spl`），换算只用一个偏移（`offset_db`）。

### 做不到的部分

严格意义上的绝对声压级验证做不到，软件**不能假装做得到**。
`Calibration::dbfs_to_dbspl` 返回 `Option` 而非「尽力而为」的 f64 是刻意的：
调用方必须显式处理未校准的情况，不能不小心把相对电平当绝对声压级报出去。

两个近似（都要标注不确定度）：

- 手机 SPL App 对照——未校准手机典型 ±5–10 dB
- 真做法律用途就买 94 dB@1 kHz 声校准器（约 ¥1000），
  那是唯一能让 dB SPL 主张站得住脚的东西

## 五、倍频带：这是近似，不是合规

`octave::OctaveBank` 每带用 4 阶 Butterworth 高通（`fc/√2`）+ 4 阶
Butterworth 低通（`fc·√2`）串联。裙边比 IEC 61260 Class 1 要求缓。

**它足以回答「低频段有没有能量」和「这一带的频谱长什么样」，
但不能用于出具合规的频谱报告。** 需要合规报告时换 FFT + 标准窗函数。

各带在设计时按其中心频率处的实际响应做了功率归一化，所以各带读数在中心
频率上一致、可直接横向比较。

注意白噪声下各带读数**不相等**：每个倍频程的带宽正比于中心频率，所以
白噪声下每带能量按 **+3 dB/倍频程**递增。31.5 Hz 到 1 kHz 是 5 个倍频程，
理论跨度 15 dB。任何「各带应大致相等」的期望都是错的。

## 六、反馈啸叫与为什么不做 AEC

麦克风和音响在同一台机器上，回放会被自己的麦克风录到 → 重触发 → 无限循环。

**明确不选 AEC，理由具体而非偏好：**

1. **AEC 会删掉我们想要的信号。** WebRTC AEC3 / speexdsp 的内部高通都瞄准
   语音频段（80–150 Hz 以上）。目标频段是 20–200 Hz——能有效消除 50 Hz
   回放的 AEC，同样会消除邻居的 50 Hz 脚步。
2. **没有时钟对齐。** WASAPI shared / CoreAudio 下采集与回放是独立时钟，
   AEC 需要远端参考信号与麦克风采样时钟对齐，得配漂移估计 + 分数延迟
   重采样器——数周工作量，收益接近零。
3. **不完整的 AEC 比没有更糟。** 它给人虚假的安全感，残留回声会间歇性越过
   阈值——从「必然啸叫」变成「每 40 次回放啸叫一次」。
4. 消费级喇叭在 50 Hz 几乎放不出能量，真正耦合进来的主要是 200 Hz 以上的
   失真产物，而触发链本来就忽略那部分。

改用**半双工 + 冷却期**，代价是回放期间听不到楼上。可接受——单次回放
200–800 ms。
